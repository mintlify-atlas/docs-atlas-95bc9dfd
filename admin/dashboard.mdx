## Overview

Sistema Viajes has two separate dashboard views, one for each role. The correct dashboard is loaded automatically after login based on the user's `rl_id`.

## Standard user dashboard

**Route:** `GET /dashboard`  
**View:** `views/dashboard.ejs`  
**Access:** Role `2` (Usuario) — redirected here after login.

The standard dashboard is shown to users with `rl_id = 2`. Because the login controller does not write a session for these users, `req.session.usuario` will be `undefined` inside this view.

<Note>
  The standard dashboard does not have access to any admin routes. Navigating directly to `/viajes`, `/colaboradores`, `/sucursales`, `/transportistas`, or `/reportes` while logged in as a role `2` user will return `403 Acceso denegado`.
</Note>

## Admin dashboard

**Route:** `GET /dashboardAdmin`  
**View:** `views/dashboardAdmin.ejs`  
**Access:** Role `1` (Gerente de Tienda) only.

The admin dashboard is the central navigation hub for all management features. It provides quick links to every module in the system.

## Navigating between dashboards

Both dashboards include navigation links to the modules the user is permitted to access. The admin dashboard renders links to all five feature modules. The standard dashboard does not render links to admin-only routes.

There is no route to switch roles without logging out and logging back in with a different account.

## Logout

Sending a `GET` request to `/cerrar` ends the current session for both dashboard types:

```http
GET /cerrar
```

<Steps>
  <Step title="Destroy the session">
    `req.session.destroy()` is called, removing the server-side session record.
  </Step>
  <Step title="Clear the cookie">
    The session cookie is cleared from the client browser.
  </Step>
  <Step title="Redirect to login">
    The server redirects to `/index`, which renders the login page (`views/index.ejs`).
  </Step>
</Steps>
